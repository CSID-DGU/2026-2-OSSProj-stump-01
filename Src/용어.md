# 용어·기능 기준

서비스에서 쓰는 용어와 기능별 기준이다. 기획의 기준은 `Doc/2_1_OSSProj_01_stump_중간보고서.pdf`이고, 둘이 다르면 중간보고서를 따르고 이 문서를 고친다.
DB 컬럼·상태값은 `backend/db/ERD.md`, API는 `backend/openapi.yaml`에 있다.

## 사용자 역할

- 지나가는 시민: 명판 QR을 찍고 로그인 없이 나무 페이지를 보며 좋아요·한 줄 응답·이상 신고를 남긴다.
- 돌보미: 구청 승인을 받아 나무를 돌보는 시민. 한 명이 여러 그루, 한 그루에 여러 명(다대다)이다. 문서·화면 전체에서 '입양자' 대신 '돌보미'만 쓴다.
- 단체 관리자: 환경단체·학교·기업의 관리자. 역할이 아니라 단체 멤버십이며, 관리자도 자기 나무를 돌보는 돌보미다.
- 구청 담당자: 관리청 녹지 부서 담당자. 자기 관리청의 신청·보고서·물품·신고만 처리한다.

## 기능

- 돌보미 신청서: 돌볼 나무·활동 기간·참여 동기. 상태는 `대기 / 승인 / 반려 / 종료`. 반려하면 사유를 남긴다. 항목은 구청 양식 확인 후 맞춘다(#59).
- 날짜별 활동 기록: 리뷰 쓰듯 사진 + 활동 선택 항목 + 짧은 글 + 활동 시간. 날짜는 자동으로 채운다. `records.type = activity`.
- 이상 신고: 유형 + 사진 + 위치 + 나무 ID. `records.type = report`. 공개 게시하지 않는다.
- 월간 보고서: 아직 보고서에 묶이지 않은 기록이 있는 날짜를 골라 구청 양식 순서로 자동 작성한다. 제출한 날짜는 다시 고를 수 없다. 구청이 `승인 / 보완 요청`한다.
- 봉사시간: 구청이 승인한 보고서 한 편에 한 번만 기록한다(보고서 번호 유일 제약).
- 물품 지급: 쿨토시·모자 같은 활동 물품을 `신청 → 승인 → 수령`으로 끝낸다. 반납·기한이 없고, 재고만 구청이 관리한다.
- 한눈에 보기: 구청 웹 첫 화면. 검토 대기 보고서, 미제출 돌보미, 승인 대기 신청·물품, 미처리 신고, 이달 봉사시간을 관리청 기준으로 보여 주고, 숫자를 누르면 처리 화면으로 간다.
- 관리 사각지대: 돌보미가 없거나 이번 달 활동이 끊긴 나무.
- 신고 처리 큐: 관리청별로 배정된 신고 목록. 미처리 경과일순으로 정렬한다.
- 나무별 공동 이야기: 한 나무에 여러 돌보미가 글을 덧붙이는 이야기. QR 이야기 페이지에서 로그인 없이 본다.
- 받은 호응: 지나가는 시민이 이야기 글에 남기는 좋아요·한 줄 응답(80자). 같은 기기는 글 하나에 하루 한 번. 알림과 나이테 표식으로만 쓰고 순위에는 넣지 않는다.
- 고마워요 반응·스탬프·배지: 기록을 저장하면 나무의 고마워요 반응과 스탬프가 나온다. 스탬프는 기록 수로 계산하고, 5·10회에 '우리 동네 나무돌보미' 배지를 준다. '아픈 나무가 낫는' 연출은 쓰지 않는다.
- 활동 순위 / 공식 순위: 활동 순위는 돌본 나무 수·누적 활동으로 실시간 상위 10명을 보여 준다(사진 있는 기록만, 같은 나무 하루 1회, 폭염특보 날 낮 활동 제외). 공식 순위와 이달의 MVP는 승인된 봉사시간으로 계산한다.
- 오늘의 날씨: 기상청 단기예보·특보로 최고기온과 특보를 받아 활동 추천 시간을 정한다. 일 최고기온 33℃ 이상은 폭염이다.
- 수종별 기본 콘텐츠: 기록이 적은 나무 페이지에 보여 주는 수종 특징·계절 변화 카드와 같은 동·노선의 나무 수·돌보미 수. 가로수 데이터에 나무 나이는 없다.
- 디지털 나이테: 1년 1겹, 월별 12조각. 두께 = 받은 비와 돌봄, 색 = 더위, 점 = 활동한 날, 별 = 이야기(누르면 작성자의 이야기 페이지로 이동), 표식 = 신고·조치·받은 호응. 두께는 돌보미 개인 활동이 아니라 나무가 받은 것으로 정해 돌보미가 자책하지 않게 한다.
- 돌보미 교육: 교육 카드 + 문제은행 퀴즈(Should). 물주기 영역은 없다. 영역 비율은 #34에서 정한다.

## 범위

- 우선순위: Must(한 바퀴에 꼭 필요한 기능, 먼저 한다) / Should(최종 발표 전 목표) / Could(여유가 있을 때) / Won't(네이티브 앱).
- 범위에서 뺀 것: 입양(유료·나무당 1명), 물주기 기록, 물 필요도·건강 상태 계산, 관리기금, SBT, 관찰 12회 추적, 구→동 드릴다운.

## 목표

- 최종 발표: 시민 웹에서 신청 → 구청 심사 → 날짜별 활동 기록 → 월간 보고서 제출 → 구청 검토·봉사시간 기록 → 시민 웹에 반영되는 한 바퀴가 끊김 없이 동작하고, Should(나이테·스탬프·순위·상부 보고 집계·교육)까지 구현한다.
- 모바일 브라우저에서 QR로 열었을 때 설치·로그인 없이 나무 이야기 페이지가 바로 보인다.
- 시민 웹은 모바일·데스크탑 두 레이아웃으로 나눈다(태블릿은 모바일과 같음). 데스크탑에서는 QR 안내·현장 사진 촬영·홈 화면 추가처럼 현장 기능을 숨긴다. 구청 웹은 데스크탑 레이아웃만 둔다.
- 기록 검증: 나무 근처 위치가 확인되지 않으면 사진 첨부를 필수로 받는다.
